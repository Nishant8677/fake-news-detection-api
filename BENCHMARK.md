`results/classification_report.txt`, generated by `benchmark.py`. Both files are
committed. Re-run with `python benchmark.py` to reproduce.

## Model quality — read this before quoting the serving numbers

The classifier is a fine-tuned BERT on the **6-class LIAR** task
(pants-fire / false / barely-true / half-true / mostly-true / true), n=1267 test claims.

| Metric | Value |
|---|---|
| Accuracy | **0.2573** |
| Macro F1 | 0.2601 |
| Weighted F1 | 0.2553 |

Per-class F1 ranges from 0.19 (mostly-true) to 0.31 (pants-fire). Random chance on a
balanced 6-way task is 0.167.

**This is the number an interviewer will ask about, so own it first.** Fine-grained
6-way LIAR is a notoriously hard benchmark — published results sit far below what
people expect from a BERT fine-tune, and the original benchmark paper reported
comparable figures. **Verify the current published range yourself before citing it**;
do not quote a SOTA number you haven't checked.

The honest framing: this project is about **serving engineering** — containerization,
latency, batching, structured logging — on a model whose ceiling is set by the dataset,
not by the training. Claiming otherwise would be worse than the 25.7%.

## What is NOT claimed here

- No claim that this model is accurate enough for production use.
- The single-request throughput (117.9 req/s) and batch throughput (396.5 req/s) are
  different measurements. Cite the batch figure only when saying "batch."
